# Mobile frontend audit — 2026-10-03

## Repairs

- Added a single guarded auth router. Patient, nurse, doctor, admin and unsupported paramedic sessions now go to an intentional workspace; cross-role routes are redirected. Password changes clear the old session.
- Centralized the React Query client. Login/logout and account changes clear cached data, disconnect chat sockets and prevent stale startup or refresh requests from restoring a signed-out account.
- Hardened the API client: concurrent 401 responses share one refresh request, refresh rotation updates in-memory auth state, public auth calls never recursively refresh, non-JSON errors preserve their HTTP status, 204 responses work, multipart boundaries are generated by fetch, and configurable `EXPO_PUBLIC_API_URL` is supported.
- Fixed chat response handling and thread navigation. Messages no longer expect a second response envelope, newly created threads use the backend thread id, live events are scoped to the current thread, delivered messages cannot downgrade READ state, and failed sends preserve drafts.
- Replaced dummy voice recording/playback objects with Expo Audio hooks and added microphone configuration. Browser media uploads now send actual file blobs. Expo SDK 57 documentation was used for the audio and location integrations ([Expo Audio](https://docs.expo.dev/versions/v57.0.0/sdk/audio/), [Expo Location](https://docs.expo.dev/versions/v57.0.0/sdk/location/)).
- Replaced simulated GPS coordinates with permissioned `expo-location` capture and valid coordinate checks. Saved and manual location entry no longer submits the Lahore fallback coordinates.
- Recurring-care setup now opens the real care-request form. The nurse schedule now renders fetched visits with day/week/month navigation, date filtering, loading/error states and retry behavior.
- Added doctor and paramedic role choices plus paramedic registration fields and explicit unsupported-role handling. OTP entry validates numeric six-digit codes and offers resend.
- Corrected cancelled visit handling and invalidated the right clinical query key after risk assessment.
- Removed 162 compiler-confirmed unused imports and updated the Expo Audio dependency.

## Verification

- Mobile TypeScript check passed with `tsc --noEmit`.
- Mobile regression suite: 15 tests passed.
- Expo web export passed and generated all 161 static routes.
- ESLint remains noisy: the installed React Compiler rules report 116 existing errors and 61 warnings across legacy screens (mostly hook purity/effect rules and text escaping). The dependency tree was repaired enough to run ESLint, but the full legacy lint set was not rewritten in this pass.

## Remaining scope

- Real device permission prompts, native audio recording/playback, GPS accuracy and production API connectivity need device or staging verification.
- The mobile app still contains several pre-existing duplicated/legacy route groups reported by Expo as static aliases. They build successfully and were left intact to avoid breaking existing deep links.
- Generated local export folders are disposable build output and should not be committed.
