1. Executive Summary

This report documents the architectural, code-level inspection of the entire Healix codebase. Code existence was strictly distinguished from real end-to-end functionality.

  • Core Care Engine: Fully operational from Care Request → Marketplace Bidding → Bilateral Contract Approval → Visit Generation with ACID transaction guarantees.
  • Clinical Decision Support (CDSS): Multi-modal risk scoring formula (45% ML + 30% Vitals Deviation + 20% Nurse Confidence + 10% NLP Notes) successfully calculates risk tiers, establishing SLAs and auto-assigning doctors.
  • Paramedic Portal Missing: While models and chat links exist, mobile/src/app/(paramedic) does not exist, and logging in causes an auth redirection deadlock.
  • Ambulance Fleet Management is Backend-Only: RESTful CRUD endpoints exist, but neither mobile nor web admin provides an ambulance management interface.
  • Doctor Decision Gaps: Mobile action screen lacks decision selection; Web portal sends mismatched fields causing HTTP 400 Bad Request.
  • SLA Timeout Worker Failure: The worker crashes due to a PostgreSQL foreign key constraint violation on 'SYSTEM', blocking 5-minute broadcast escalations.

3. Critical Defects & Runtime Issues

CRITICAL DEFECT #1: SLA Timeout Worker Foreign Key Failure
File: backend/src/domains/care/clinical/workers/sla-timeout.worker.ts (Line 36)
Defect: Worker attempts to create an AssignmentLog with assignedTo: 'SYSTEM'. However, AssignmentLog.assignedTo enforces a foreign key constraint referencing users.id. Because no user with ID 'SYSTEM' exists, PostgreSQL throws a foreign key constraint violation and rolls back the transaction.
Impact: Cases breaching the 5-minute professional SLA get stuck in PROFESSIONAL_BROADCAST and fail to escalate to GENERAL_BROADCAST.
CRITICAL DEFECT #2: Doctor Decision Zod Validation Mismatch on Web
Files: web/src/pages/doctor/CaseReview.tsx (Line 75) & backend/src/domains/identity/doctor/doctor.validation.ts (Line 39)
Defect: Web portal sends { recommendation, actionType, urgency } to POST /cases/:caseId/decision. However, the backend controller validates against decisionSchema, which strictly requires { decision, justification, autoDispatch }.
Impact: Submitting clinical decisions on the Web fails with HTTP 400 Bad Request.
CRITICAL DEFECT #3: Paramedic Mobile Auth Redirection Loop
File: mobile/src/app/_layout.tsx (Lines 39, 65)
Defect: In getDashboardRoute(), the PARAMEDIC role falls into the default case which returns '/(patient)/(tabs)/home'. Then, the authorization guard blocks the paramedic because user.role !== 'PATIENT', repeatedly re-navigating to the same path.
Impact: Paramedics cannot log into the mobile app and become trapped in an infinite routing loop.
